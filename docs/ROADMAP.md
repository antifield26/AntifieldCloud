# 路线图

## v0.1.0（当前）

- 单管理员密码 + TOTP、恢复码、限流、CSRF、审计。
- 云盘：拖拽多文件上传（进度）、目录、搜索、图片/文本/Markdown/PDF 预览、Range 下载、回收站、10 GiB 配额。
- 门户：主机指标、存储、Minecraft 状态/玩家/TPS/白名单数、opencode 健康、服务状态、备份状态、最近活动。
- Minecraft：只读状态 + 白名单增删（RCON，复核、审计）。
- `ai.example.com` 统一登录反代 opencode。
- Cloudflare Tunnel + nftables + systemd + Windows 每日备份 + 恢复文档。

## 二期候选（按价值排序）

1. **文件分享链接**：带密码/过期/下载次数，独立审计；需要额外的公开路由与限流设计。
2. **备份可视化管理**：面板列出现有归档、手动触发、恢复向导；避免命令行操作。
3. **音视频在线播放**：Range + 转码可选；注意 Pi CPU 与 SD IO。
4. **WebDAV / rclone 挂载**：只读或读写，需处理锁、并发、配额；比自研同步客户端性价比高。
5. **PWA / 手机安装**：离线壳、安装引导、拍照上传；不引入推送。
6. **Minecraft 启停**：通过窄权限 root helper（固定命令）而非全量 sudo；需要二次确认与窗口。
7. **Cloudflare Access 第二层**：邮箱/身份策略；与应用 TOTP 叠加。
8. **SSD 迁移**：USB/NVMe HAT；迁移 `/var/lib/antifieldcloud` 与备份临时目录；评估功耗/散热。
9. **备份加密**：age/restic；PC 端保存密钥；恢复演练。
10. **监控告警**：磁盘、温度、服务、备份超期；邮件/微信 webhook。
11. **笔记/书签/照片**：独立小应用，共享登录与导航；照片缩略图需要 native 依赖或浏览器端缩略。
12. **多用户与权限**：目前单管理员；多用户需要角色、配额、审计隔离，工作量较大。

## 明确不做（至少近期）

- 多租户/SaaS 化、公开注册。
- 端到端加密同步客户端（Syncthing 式）——与 Web 云盘定位冲突。
- Minecraft 任意 RCON 控制台/插件管理。
- 在 Pi 上跑重型媒体转码/大模型推理。
- 替换现有 Minecraft/SakuraFRP/opencode 服务。

## 已知限制

- SD 卡单盘、无 RAID；每日备份依赖 PC 与直连网线。
- 回收站 30 天自动清理，不支持版本历史。
- 文件名搜索，不支持全文检索。
- 单进程；限流状态重启即清空。
- opencode 升级可能导致 SSO 行为变化，需要复测。
- 备份包含 TOTP secret，PC 端目录安全是最后防线。
